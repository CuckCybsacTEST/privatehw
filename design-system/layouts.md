# Layouts

## Overall shell

- Use a dark page shell with clear content boundaries.
- Center major content within a max-width container.
- Allow media-led pages to expand wider when needed, but keep text columns readable.
- Keep primary navigation and critical actions reachable without excessive scrolling.
- Use layered atmospheric backgrounds with soft radial glow, not busy textures.

## Page structure

Recommended page anatomy:

1. Top navigation or contextual header.
2. Hero or page title area.
3. Main content blocks.
4. Supporting panels, cards, galleries, or pricing modules.
5. Empty, loading, or helper states when content is missing.

For this product type, the home page should tease the experience, not reveal the entire catalog at once.

## Spacing strategy

- Use generous top-level spacing to separate sections.
- Use moderate spacing inside cards and panels.
- Keep vertical rhythm consistent between similar section types.
- Preserve air between the headline, the CTA, and the first preview block so the page feels luxurious.

## Breakpoints

Use simple breakpoints and let content drive the exact layout:

- small mobile
- regular mobile
- tablet
- desktop
- wide desktop

## Responsive behavior

- Mobile first by default.
- Collapse multi-column layouts into one column when content readability drops.
- Reduce density before reducing legibility.
- Keep primary actions visible and reachable on small screens.
- Ensure gallery, preview, and membership sections remain swipeable or scannable on mobile.

## Navigation layout

- Desktop can favor horizontal navigation plus utility actions.
- Mobile can use bottom navigation or a compact stacked pattern.
- If a sidebar exists, it should not overwhelm the content column.
- Keep the top-level navigation short and invitation-like.
- If an age gate is present, place it before content access, not buried in a settings flow.

## Dashboard layout

- Put summary metrics above deep operational content.
- Group related controls near the content they affect.
- Use a predictable card grid or section stack.

## Form layout

- Use one dominant column for complex forms unless comparison is necessary.
- Group related fields into clearly titled sections.
- Keep action rows near the end of the form and visible without hunting.

## Table and list layout

- Leave room for scanning rows.
- Keep filters and search close to the table.
- Avoid squeezing too many columns into one view.

## Modal and drawer layout

- Keep overlays centered or anchored in a way that matches the task.
- Do not make the overlay feel heavier than the page content unless the action is critical.
- The +18 confirmation modal should dominate the viewport enough to feel private, but remain easy to dismiss.

## Media and content layout

- Use strong framing for media cards and content previews.
- Preserve aspect ratio where visual balance matters.
- Avoid random tile sizes unless the structure supports it intentionally.
- Favor cinematic crops, subtle gradients, and soft glass-like separation over loud collage layouts.
